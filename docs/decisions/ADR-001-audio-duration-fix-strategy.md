# ADR-001: 音频时长偏移检测与修复策略

## 状态

Accepted

## 日期

2026-04-25

## 背景

在日语字幕流水线中，从 MP4 视频提取的音频解码时长(ADD)小于容器报告时长(CD)，
导致 whisperX 时间戳与视频时间轴存在比例偏移（视频 12:22 对应音频 12:18，
偏差率约 0.55%）。

原始视频 LongTest1.mp4 数据：
- CD: 2441.87s
- ADD: 2428.40s（WAV 解码后实际采样数 → 物理录音时长）
- 偏差: +13.48s (+0.555%)
- 帧率: 29.83 fps (VFR)
- 源: OBS 录屏

## 诊断结论

### 视频没问题
VFR 是 OBS 的正常行为，不是缺陷。视频最后一帧 PTS (2441.83s) 与音频最后包 PTS (2441.79s) 一致，
两个流的存在时长匹配。

### 根因: AAC 编码特性
AAC 编码器在末尾写入约 613 帧零填充帧（padding），容器将这些填充帧的时长计入总时长。
解码器自动丢弃填充帧，导致解码后音频内容比容器报告的少 13.48s。

这不是"缺陷"——几乎所有 AAC 文件都有编码延迟和填充帧。
这是一个需要在应用中处理的已知编码器特性。

## 决策

采用 3 层修复策略，优先级从高到低:

### 方案 B（首选）: VocalSeparator 提取时 aresample 对齐

`SRT/VocalSeparator._prepare_audio()` 中：
1. 提取 WAV → 测量文件大小 → 算 ADD
2. 对比 CD（来自 `_get_media_duration`）与 ADD
3. 若 abs(CD-ADD) > 0.5s → 用 `-af aresample=async=1:first_pts=0` 重提

**原理**: aresample 对整个音频进行均匀重采样拉伸（对 LongTest1 为 0.55%）,
使解码时长与容器一致。0.55% 拉伸人耳不可感知。
**代价**: 重提增加约 2.5s 额外耗时（仅非 CFR 视频触发）。

### 方案 C（兜底）: SRT_Extract 比例修正

`SRT_Extract.extract_with_whisperx()` step 8.5 中：
提取后音频时长与视频容器时长不符时，所有 timestamp 乘以 CD/ADD 比例。

### 方案 A（已废弃）: VFR→CFR 视频重编

最初认为 VFR 导致容器时长虚高，尝试 `-vsync cfr -r 30 -c:v libx264 -c:a copy`。

**废弃原因**: 即使重编了视频（VFR→CFR），音频流解码后采样数不变，
ADD 仍然只有 2428.40s。视频重编不能增加音频内容长度。

实验验证：CFR 重编（含音频重编码）后提取音频仍为 2428.40s（与原始提取完全一致）。

## 替代方案考虑

### apad 补静音
- 用 `-af apad=whole_dur=CD` 补零到容器时长
- 被拒: 最后 13s 静音会破坏时间定位精度（字幕出现在视频的最后 13s）

### 仅比例修正
- 不改音频，只修正时间戳
- 保留为兜底方案（方案 C）
- 缺点: 不改音频，下游一切依赖时间戳的工具都需要后处理

## 后果

### 正面
- 流水线自动检测并修复音频时长偏移
- 无人工介入，零误判（有兜底）
- 视频保持原始质量（不被重编码）
- 方案 B 的性能损失仅限于非 CFR 视频

### 负面
- 0.55% 音频拉伸理论上会改变音高（440Hz→442.4Hz），但人耳不可感知
- 如果原始音频已经有时间戳，aresample 会覆盖它们

### 迁移注意
- 现有流水线不需要改动——`VocalSeparator._prepare_audio()` 默认已启用方案 B
- 新视频自动检测，无需配置
